# story-html-v2 — 실제 화면 위를 나는 카메라로 읽는 스크롤 스토리

제품을 실제로 띄워 화면을 찍는다. 각 장은 그 캡처 한 장을 브라우저 창에 담고, 스크롤에 따라 **카메라가
읽어야 할 곳으로 날아가고**, 링과 돋보기가 그 자리를 짚고, 데모 커서가 문장이 말하는 일을 직접 누른다.
타이핑·스트리밍은 녹화한 프레임을 넘겨 보여 주고(다시 그리지 않는다), 창 아래 어두운 패널은 그 화면이
**어떻게 동작하는지**를 노드·간선·패킷의 모션 그래픽으로 그린다. 옆 칸에는 주장 한 줄과 그 단계의 근거
원문이 붙는다. 읽는 사람은 **스크롤만으로** 무엇을 어떻게 만들었는지 본다.

- 출발점: [assets/starter/](assets/starter/) — `capture.mjs`(실제 화면 촬영·익명화·박스 측정·녹화) +
  `shots.config.mjs` + `src/`(engine · kit · **app.js**(AppCam · Mech · Graph · box/seq) · base · boot ·
  data · page · chapters) + `build.mjs`(캡처 내장) + `check.mjs`. 가상 상점 데모 앱(`demo-app/`)과 그
  캡처로 그대로 빌드되는 예시 3장(ch-hero · ch-refund · ch-end).
- 디자인 시스템 전문: [references/grammar.md](references/grammar.md) — 처음이면 §2 바닥 · §3 천장 · §6 장
  문법 · §7 API · §10 함정을 읽는다.
- 촬영·익명화: [references/capture.md](references/capture.md).
- 기준 화면: [references/captures/](references/captures/) — 시작 전에 직접 열어 본다. 글보다 화면이 기준이다.
- 장을 여러 에이전트에 나눌 때: [references/contract-template.md](references/contract-template.md).

## 작업 순서

1. **내용 → 장 설계.** 출처 문장(README·개발 기록·스펙·이력서)을 `data.js`의 `NOTES`에 원문 그대로 모은다.
   장 = 제품의 한 기능(화면) 하나, 장마다 4–7단계. 모든 장을 관통하는 **주인공 대상 하나**(이슈 번호,
   주문 하나, 검색어 하나)를 정한다. 장마다 "카메라가 볼 곳 · 커서가 할 일 · 패널이 그릴 원리"를 적는다.
2. **출발점 복사.** 기본 위치 `~/Documents/new-html/projects/YYYY-MM-DD-<name>/`(사용자가 지정하면 그곳).
   `cp -R <skill>/assets/starter <dest>`. 스킬 안의 starter는 고치지 않는다.
3. **촬영.** 제품을 띄우고 `shots.config.mjs`에 장면별 상태(url · before 단계)와 **가리킬 요소의 박스**를
   적는다(문장 속 한 구절은 `{ selector, text }` 박스로). 타이핑·응답은 `type`/`record`로 녹화한다. 촬영은
   기본이 읽기 전용(GET 외 요청 차단)이라 누군가의 실제 도구를 찍어도 데이터가 바뀌지 않는다. 공개 페이지면 실명·회사·호스트를 `redact.local.mjs`
   (git 제외)에 적어 촬영 때 DOM에서 바꾸고 `forbid`로 막는다. `node capture.mjs` 후 **모든 캡처를 열어
   본다**(이미지·이니셜·슬러그는 글자 치환이 못 잡는다). 실행할 수 없는 제품은 재구성 페이지를 만들어
   같은 방식으로 찍는다(capture.md §5).
4. **셸 채우기.** `page.html`의 title · HUD · 장 섹션(`<!--ch-x-->`, `data-chapter`, `data-org`,
   `data-period`, `--len`), `base.css`의 `--cite-label`, `data.js`의 HERO·출처.
5. **장 만들기.** `src/chapters/ch-x.js|css`를 `AppChapter` + `CAM`(keys · marks · cursor · sequence) +
   `Graph`로. 좌표는 전부 `box("shot", "name")` — 눈대중 좌표 금지. 장이 많으면 촬영·공용 파일을 먼저
   확정하고 장마다 에이전트를 나눈다.
6. **검증.** grammar.md §11 캡처(1440×900 · 1280×720 · 390×844 · `REDUCE=1` · 장 사이 `@enter`)를 찍고
   PNG를 직접 연다: 링이 화면 안·정확한 요소 위에 있는지, 커서가 누르는 순간 대상 위인지, 라벨이 대상을
   가리지 않는지, 돋보기가 읽어야 할 글자를 보이는지, 패널 그래프가 그 단계와 맞는지. `_log.txt` 0,
   `lowFill` 0. 공개면 금지 패턴·grep 0.
7. **배포.** `node build.mjs --publish=<repo>/public/...html`. 커밋은 사용자가 요청할 때만.
   `redact.local.mjs`·원본 캡처·로그인 상태 파일은 어떤 공개 저장소에도 넣지 않는다.

## 바닥 — 하나라도 빠지면 미완성

- **실제 캡처가 주인공**: 장마다 창(주소창 = 호스트 + 경로) 속 실제 화면. 다시 그린 목업·카드 나열로
  대신하지 않는다. 캡처 날짜 스탬프(`2026-10-23 화면`), 재구성·연출 상태는 `재구성 · …`로 밝힌다.
- **카메라가 시선을 이끈다**: 단계 경계마다 키, 데스크톱 프레이밍은 캡처 1060px보다 좁히지 않는다.
  작은 글자는 더 확대하지 말고 **돋보기**(`lens`)로 읽힌다.
- **링 + 라벨**로 짚고, 결정적 순간은 `spot`으로 나머지를 어둡게. **데모 커서**가 결과가 바뀌기 직전에 누른다.
- **녹화 프레임**으로 타이핑·응답을 보여 준다(캡처 위에 글자를 덧쓰지 않는다).
- **메커니즘 패널 = 모션 그래픽**(Graph): 상태·흐름·개수를 노드·간선·패킷·셀로. 글 줄 나열은 예외.
- **단계마다 원문 인용**, 모든 원문 줄이 어딘가에 한 번. 제목은 제품에 대한 주장 두 줄, `<em>` 하나.
- **여는 장면은 내용을 해석**하고, **마지막 장은 다음 행동 + 모든 화면 모음**(누르면 그 단계로).
- **고정 레이어**(HUD · 레일 · readout · grain · 캡슐), **모드**(동작 줄이기 = 단계별 완성 상태, 모바일 한 칼럼
  + 모바일 크롭, 본문 16px · 라벨 13px 이상).

## 꼭 지킬 것 (사용자가 직접 바로잡은 것들)

- **스크롤만으로 끝까지.** 머지·결제·환불 같은 사람의 결정도 데모 커서가 스크롤에 맞춰 수행한다.
- **상태 = f(p).** 네이티브 스크롤만, 되감기·새로고침·레일 점프 어디서든 같은 화면.
- **과확대 금지** — 「너무 확대돼서 어디서 어디를 선택했는지 가늠이 안 됨」. 맥락(사이드바·헤더·옆 칸)이 보이게.
- **가독성 > 화려함.** 글 뒤 밝은 움직임 금지, 라벨이 대상을 가리지 않게, 모션이 끝나야 읽히는 구조 금지.
- **모션 정지 버튼 금지**(OS 설정만), **구호 금지**, SVG에 이모지 글리프 금지.
- **공개 페이지 익명화는 촬영 단계에서.** 치환 사전 자체가 실명 목록이므로 공개 레포에 두지 않는다.

## 바닥이지 천장이 아니다 — 페이지마다 의무

기준 페이지와 starter는 **바닥**이다. starter를 복사해 캡처만 바꾼 결과는 미완성이다. 페이지마다 둘 다에
없던 것을 **최소 두 가지** 새로 만든다: (a) 그 콘텐츠에만 있는 **시그니처 장면** 하나(기준 페이지의 일곱
레인 · starter의 행 착지 장면을 재사용하지 않는다), (b) 카메라 · 장 전환 · 물질 · 녹화 · 메커니즘 그래프 ·
타이포 · 빛 중 하나를 바닥보다 한 단계 위로(예: 클릭한 행을 뚫고 다음 캡처로 들어가는 돌리, 측정 박스를
깊이 층으로 들어 올린 시차, 실제 버튼에서 출발한 패킷이 패널 그래프로 착지). 방향은 grammar.md §3.
마지막 보고에 **“바닥 대비 새로 만든 것”**(장면 · 연출 · 위치)을 적는다.
